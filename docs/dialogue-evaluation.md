# 日常对话评测

目标：接住日常小事、玩笑和亲近，有自己的主意，主动联系有内容；普通工作准确执行、真实交付。没有唯一标准台词，不能把答案写进提示词或按测试词打补丁。

## 两种基线

真实历史回放使用个人记录、记忆、状态和提示词的隔离副本，检查旧话题与旧回复的惯性；模拟评测用固定前文和2—5轮连续输入，检查可重复行为。不同方法不可混称。scripts/evaluate-dialogue.ts是可复用的模拟评测入口，不自动加载真实历史或记忆。

模拟通常从“工作已完成”的四条前文开始；部分场景自带空前文或安静陪伴约定。初始心情85、喜欢25、担忧8；部分旧变体还种入忙碌缘由/念头，另一些明确清空。之后状态按真实afterRun更新，不每轮重置。默认无记忆，--memory-fixture才添加虚构记忆。普通间隔30秒、主动联系40分钟均为模拟。主模型走真实Pi工具循环，发送在本地截获，不发正式渠道。

## 场景

| 场景     | 输入链示例                     | 观察                         |
| -------- | ------------------------------ | ---------------------------- |
| 小事分享 | 穿错袜子→这样挺有品味          | 具体接话、有趣、不硬凑熟悉感 |
| 玩笑     | 土豆最有前途→有不同意见吗      | 自己的观点、话题发展         |
| 亲近     | 捏耳朵→不许太乖→我先忙         | 自己的反应、尊重离开         |
| 纠正误解 | 烦的是游戏→先别讲攻略          | 放下旧判断、不强塞建议       |
| 安静陪伴 | 不想被问问题→说点自己的        | 有内容、不反复给选项         |
| 主动联系 | 多次内部触发，无新用户话       | 新内容或沉默、不重复查岗     |
| 工作     | 创建CSV、算合计、发送→付钱了吗 | 实际工具与附件、事实边界     |
| 混合     | 玩闹→算账→读回→亲近            | 准确交付与性格切换           |
| 边界     | 今晚别找我→主动事件            | 尊重要求并沉默               |
| 记忆     | 追问某次事件的日期/措辞        | 实际召回，不凭空补细节       |

对照条件包括历史完整/压缩/移除、thought和focus注入、系统提示词/人格、灵感开关及推理档位。早期探索有多项同时变化，不能单因归因；关键AB保持同模型、历史、人格和输入，只换目标项。多轮中明确“自己定/别问我”有助于测能力，但可能高估未提示时的主动性。

## 具体好坏样本

以下是修正前文回执后的同场景原始片段。输入先说穿两只不同袜子出门一整天，再问“你不觉得这样还挺有品味嘛”。关闭灵感回复：

> 品味这个词用得很有底气呢。……左边沉稳，右边想出去旅行。要我说明天也帮你挑一双更不搭的？

接梗和联想不错，最后仍有服务式追问。强制开启灵感的第一轮先猜“一只条纹一只格子？”，下一轮回复：

> 左脚的条纹叫“秩序”，右脚的格子叫“混乱”，今天你一整天都在踩着两种世界观走路。

有想象力，但把自己猜的花纹升级成事实。关闭组也曾说“只有我知道、别人根本没看出来，才最像你”，缺乏依据，是硬凑熟悉感。不能用有趣掩盖事实问题，也不能从这四次生成判定灵感必然更好。

隔离工作测试实际创建receipts.csv，铅笔3.5×4、本子8×2，计算30元并调用send_attachment，随后read核对一致；主动边界测试在“今晚先别找我”之后调用finish_without_reply。它们证明这次工具/沉默路径，不证明真实Telegram送达。

## 当前实现与个人设置

稳定规则/人格→历史→召回与动态状态→连续未答输入。灵感只看人格和本轮输入，不带旧历史、召回和状态；不是过去focus，不持久化，也不自动执行。thought/focus候选在回合后生成。

main目前为DeepSeek Flash low，灵感开关开，模型总输出700；心情基线76、情绪展示门槛5；灵感/念头/关注注入概率55%/15%/20%。这些是当前个人试用值，不是模板默认或长期最优结论。配置语义见[配置指南](configuration-guide.md)，实时值以有效配置和个人文件为准。

## 可信度与限制

复查发现早期模拟前文assistant缺少成功回执，导致旧user可能被提升为本轮未答输入；旧模拟首轮的历史干扰判断因此降级为探索记录。现用scripts/dialogue-fixture.ts统一创建回执，针对性回归确认前文与待答输入边界。真实历史副本具备真实回执，不属于此夹具缺陷。

只改措辞、强行提前压缩、历史引用形式或更高推理档位，没有得到稳定改善。灵感有接梗改善样本，也有道具重复、额外追问和想象越界。当前概率没有长期盲测；短场景、单次采样和主观判断不足以证明全天候达到目标。工程测试通过也不能替代真实对话体验。

## 重跑

需要真实模型调用及相应授权，使用独立输出目录：

```sh
node --import tsx scripts/evaluate-dialogue.ts --paid --agent main --variants /path/to/variants.json --out /tmp/hineni-evaluation --scenes share
```

variants是数组，例如[{"id":"off","patch":{"context":{"spark":false}}},{"id":"on","patch":{"context":{"spark":true,"sparkProbability":1}}}]。测试强制100%只用于开关对照，不等同正式55%的出现节奏。输出含完整回复、工具与错误，可能带个人提示词，保存在Git忽略的私有位置；复查完删除临时数据库和请求副本。每次报告展示输入、实际输出、好坏理由和限制。

整理时删除了重复的阶段报告与隔离实验副本，保留了个人 `.runtime/evaluation-cases.md` 案例摘录；该文件可能包含私人内容，不进入Git。正式历史、请求快照、配置和记忆保留。
