# 工作台使用与调试

地址：http://127.0.0.1:8788 。刷新旧页面后，用 `.env` 的 HINENI_TOKEN 登录。令牌只保留在当前浏览器会话；点击“更换管理口令”可重新输入。

## 每个页面做什么

| 页面          | 操作                                                                                                                               |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Telegram 接入 | 填 Bot Token、Chat ID、话题 ID；绑定当前 agent；查看已见聊天和对应 config.yaml 字段                                                |
| 工作台        | 当前 agent 的事件时间线；聊天、附件、取消工作；筛选或加载更早记录；勾选删除原始记录，或清空当前 agent 全部原始记录；压缩摘要单独清空 |
| 执行与工具    | 按 agent 选择 run，展开工具输入和结果；查看完整工具 JSON、终端 stdout；追踪末尾或下载；查看投递失败与重试                          |
| 上下文        | 跟随最新 run/请求，或选中历史请求；查看可折叠 JSON、原文、下载；图像保留元数据，不展示 base64                                      |
| 配置          | 数字输入、开关、枚举和嵌套对象/数组表单；公共默认值或当前 agent 独立设置；保留 JSON 高级编辑                                                   |
| 模型与密钥    | 向所填服务的 `/models` 获取列表、选择模型；填写地址和容量；更新当前 agent `.env` 中的模型凭据，不回显旧值                                        |
| Agents        | 新增、编辑、启停、选择独立 agent；移出配置保留数据。新增默认停用，配置渠道后启用并保存重启                                         |
| 文件与文档    | 按人格记忆、提示词、定时脚本、工作文件、项目文档分类阅读和编辑；Skills 从独立页面进入；按版本检查保存冲突；运行记录和 state 为只读 |
| Skills        | 上传文本文件目录或 SKILL.md 与脚本，或直接粘贴说明；编辑；移除归档，下一轮不再发现                                                 |
| 程序日志      | 全局程序诊断、模型失败、召回降级、调度错误。工具明细另在“执行与工具”                                                               |

左侧 agent 下拉框同时切换个人模型、凭据、配置、文件和定时任务。配置默认编辑当前 agent；“公共默认配置”写根配置，未设置个人值的字段会继承它。详细文件位置见 [Agent 独立配置](agent-layout.md)。

## 保存、暂存、重启分别是什么意思

- 暂存到浏览器：只保存当前草稿，不改变服务。配置修改自动保留草稿，也可手动暂存；文件编辑仍需手动暂存。配置和各文件分别暂存；清理浏览器数据会丢失草稿。配置中若写了 MCP env 明文，它也会进入草稿，凭据建议使用专用密钥界面。
- 保存配置：同时提交表单和配置 JSON 的修改，校验后分别写入根默认配置和各 agent/config.yaml，再读回核对。按钮旁显示成功时间或失败原因；失败保留草稿，成功后重新绑定表单，继续修改可再次保存。此时运行组件仍等待重启。
- 保存并重启：停止旧执行和组件，重新加载配置/凭据并恢复服务；历史和可靠发送队列保留。有效配置启动失败时尝试恢复旧运行配置，并报告原因，磁盘新配置仍保留供修正。
- 保存文件：对比读取版本，避免覆盖已经被 agent 或其他编辑者修改的文件；人格、提示词和 Skill 下一轮读取。
- 重启定时脚本：只重置当前 agent 的脚本，不影响其他 agent，不应用模型等主程序设置。

保存期间暂时禁用编辑和切换，避免新修改与保存结果互相覆盖。直接点击顶部重启时，若还有配置修改，会要求使用“保存并重启”。刷新网页后可用“恢复暂存”找回自动草稿；本功能无法恢复安装更新前没有暂存的修改。

改变管理口令后需用新口令重新连接；改变管理端口后打开新地址。自动重启是主进程内组件重建，不是更新 Node 或重新编译源码。

## Telegram：Token 和 Chat ID 分别存哪里

在“Telegram 接入”先选机器人渠道，再核对当前 agent。Bot Token 负责登录，Chat ID 负责接收和回复的位置。

| 页面修改           | 保存的真实位置                                     | 用途                                           |
| ------------------ | -------------------------------------------------- | ---------------------------------------------- |
| Bot Token 的变量名 | config.yaml → channels[n].tokenEnv                 | 例如 TELEGRAM_BOT_TOKEN，这里只有变量名        |
| 实际 Bot Token     | .env → 上述变量名                                  | 点击“保存 Bot Token”写入；页面不回显           |
| 默认聊天位置       | agents/<id>/config.yaml → defaultTarget.conversation | 同时匹配输入，主动消息默认发这里               |
| 额外聊天位置       | agents/<id>/config.yaml → routes[m].conversation     | 让该 agent 接收额外私聊/群聊                   |
| 话题 ID / 类型     | 对应目标的 thread / kind                           | 区分话题及私聊、群聊                           |
| 允许列表           | config.yaml → channels[n].allowedChats             | 渠道先过滤，再匹配 agent；空数组表示不额外过滤 |

数组序号随配置变化；页面显示你当前这一项的真实路径，人工编辑时按渠道/agent 的 id 找对应项。`.env` 只有三个变量完全正常，Chat ID 不在其中。普通回复使用触发来源；`targets` 仅是跨渠道发送别名。

不知道 ID 时：保存渠道和 Token → 重启 → 给机器人发消息 → “刷新已见聊天” → 点击一个位置填入 → “加入当前 agent 的绑定” → 保存并重启。未绑定消息只登记位置，不触发 agent。已见聊天保存在 `data/runtime.sqlite` 的 kv 键 `telegram-chats:<渠道 ID>`，最多 50 个位置，仅含 ID、类型、标题、最近时间和是否允许，不保存那条未路由消息的正文。

“复制到输入框”用于建立新绑定。更换默认位置会把旧位置保留为额外接收，可在绑定列表移除。允许列表非空时，加入绑定也会将该 ID 加入允许列表。检查后一起保存。

## 模型列表和逐项帮助

“模型与密钥”每个模型槽位都能获取列表：先展开接口设置确认 baseUrl 和 apiKeyEnv，再点“根据 Key 获取模型列表”，筛选后选择。API 使用草稿中的地址，读取已保存的 Key；可临时填一个 Key 只用于这次获取，不写文件。列表包含提供方返回的全部模型，不能据此推断聊天、工具、图片支持或上下文窗口。

当前 agent 的模型写 `agents/<id>/config.yaml → models.<槽位>`，Key 写同目录 `.env`；公共默认值写根配置。模型列表使用当前 agent 的 Key。辅助槽位未指定时使用 fast。保存并重启后应用。

“配置”每个字段可展开“含义、处理流程与更新方式”，展示配置路径、流程或 prompt 的影响、默认值和覆盖范围。恢复单项或整组默认只修改草稿；“复制当前默认值”会复制根配置的当前值到个人草稿，保存后仍独立。完整表见[逐项配置说明](configuration-reference.md)。

## 工作台的三个视图

完整原始记录里，每条事件左侧有选择框。点“删除选中记录”只删勾选的原始事件；点“清空全部原始记录”删当前 agent 的全部事件，包括输入、回复、工具、投递事件和执行轮次。两者都会同步处理 SQLite、`agents/<id>/history/*.jsonl`、关联的发送队列与不再被其他记录引用的附件副本。已送达平台的消息不会撤回，其他 agent 的经历、配置、人格和记忆不变。正在执行或向平台发送时会拒绝删除，等工作结束后重试。删除无法从工作台撤销。

**压缩摘要独立。** 删除原始事件不会改动已经生成的摘要，其中可能仍描述被删对话。要清掉它，另点“清空压缩摘要”：只删除摘要检查点，保留全部剩余原文，下一轮从剩余原文重建历史视图。删除原始事件不会删除 `.runtime/requests` 和 `.runtime/traces` 里的历史上下文请求。它们可能包含当时的聊天文字，但不会被下一轮自动复用；清空执行记录后，现有上下文页面可能不再列出这些仍在磁盘上的文件。

| 视图               | 数据和含义                                                                                                       |
| ------------------ | ---------------------------------------------------------------------------------------------------------------- |
| 完整原始记录       | 第二层事件索引，默认最新 100 条，可继续加载更早；用户、回复、工具、内部事件以不同淡色表示；不使用压缩摘要        |
| 当前摘要＋剩余原文 | 当前压缩检查点加未压缩事件；工具结果按 toolTailTokens 取尾。只读预览，不触发模型或改变检查点；显示正在运行的阈值 |
| 最近实际交接       | 最近保存的初始编排快照内 layer2 材料，含当轮目标、触发 ID、交流间隔；不会混入后续事件                            |

当前预览与下一轮实际交接可能不同：下一轮才执行压缩、选择附件和预算裁切。旧版快照没有独立间隔信息时明确标示。最近实际交接查找最近 100 次运行中存在的快照，需要 context.trace。

交流间隔由第二层按同一回复目标最近一次 agent_reply 文字块提交计算，不是 Telegram 送达时间。当前预览的间隔随时间变化；实际快照保留那一轮的值。第三层按 state.gap 把它放进 state.conversation_context，并受状态背景预算影响。要看第三层人格、召回与工具迭代后的完整主模型请求，去“上下文”。

## 文件的阅读与修改

默认按“人格与记忆、提示词、定时脚本、工作文件、项目文档”分类，标题显示用途，下面保留文件名和目录。每份文件上方说明由谁更新、是否进入上下文及保存后何时生效。机器 schema、早期草案等在“显示辅助文件”后出现；Skills 从 Skills 页进入编辑，不混在日常文档中。

Markdown 默认是阅读排版，点“编辑原文”才进入宽行距编辑器。state、历史和运行记录只读；过大文件可分页或下载。人格与提示词、Skill 下一轮读取；工作产物由模型按需读取；memory.json 的词法同步和向量维护分开；说明文档本身不会自动变成 system prompt。具体作用以页面该文件的说明为准。

新输入取消未交接回复时，原始正文和相关快照会删除，工作台在下一次刷新时清掉旧缓存；相关轮次可能不再有请求快照。已交接的消息和实际工具记录保留。

## 为什么原来的日志看不到工具

工具早已通过 tool_call/tool_result 写进第二层经历，旧页面仅展示诊断日志和 run 汇总。新版直接读这些真实事件，并提供 history/tools 的完整结果和实时 stdout。不能把程序 logs 表等同于全部执行经历。

本地调试顺序：选择 agent → 工作台发任务 → 执行与工具选最新 run → 展开参数/结果 → 查看完整结果文件 → 上下文检查模型下一次请求看到的内容。

## 上下文具体保存什么

`context.trace=true` 时保留两个层次：

- `.runtime/traces/<run_id>.json`：第三层初始编排。
- `.runtime/requests/<run_id>/<序号>.json`：每次调用主模型前、经过执行器变换的 Pi 请求上下文；包含消息、system 内容和工具声明（当前 Pi 将 system 与工具声明放在消息列表中）。

这是主模型请求前快照，不是模型提供方网络报文，也不是隐藏思考的流式日志；辅助查询/心情 API 没有同样的逐请求抓包。UI 每约 2.5 秒刷新。旧运行没有逐次请求文件时回退到初始 trace。图片像素从快照中省略，其余文本完整保存；大文件分页查看和完整下载。

## Skill 安装与移除边界

安装支持最多 200 个文本文件、每文件 2 MB，目录必须含 SKILL.md。保留目录内脚本相对路径；不自动安装依赖、不自动执行脚本，不支持直接上传 ZIP/二进制或一键拉取远程仓库。外部共享目录仍通过 agents[].skills 配置。

移除把本地目录移到 `.runtime/removed-skills/`；同时记录移除清单，避免重启又装回自带 Skill。需要恢复时可重新导入备份包，或由管理员把归档目录移回。移除后的已有运行可能仍握有旧上下文，下一轮才使用新的技能目录。

## 新增的只读检查接口

- `GET /v1/admin/guide`：字段解释、分组范围、出厂默认值。
- `GET /v1/telegram/chats`：运行中 Telegram 渠道已见位置。
- `GET /v1/agents/:agent/history-view?offset=&limit=`：检查点、摘要、剩余文本分页、运行阈值与当前间隔；不压缩、不更新状态。
- `GET /v1/agents/:agent/layer2-snapshot?offset=&limit=`：最近保存的 layer2 交接材料，保留该轮间隔；旧格式标 legacy。
- 文件清单新增 category/title/purpose/effect/advanced 展示字段；读写权限沿用原规则。

文本分页默认 200k 字符，上限 1M；这里只分页剩余原文，摘要单独完整返回。

| --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |

## 参数与文件的完整说明

展开参数下方的“含义、处理流程与更新方式”，依次看保存文件与字段、含义、调整效果、具体受影响步骤、程序从读取到写回的流程、更新时机和源码位置。这里保留计算公式和限制，也用例子说明结果。表达风格项还能展开查看当前草稿生成的 [Style]；生成函数与第三层共用，最终实际内容仍受整体上下文预算约束。

文件标题下显示绝对路径，展开“这份文件如何被读取、修改并进入下一轮”查看读写流程；memory.json 和 state.json 还有逐字段说明。完整文件参考见 [文件如何参与运行](files-guide.md)。

暂存、恢复、保存和重启的说明收在底部操作栏的问号中，默认收起；文件编辑操作栏有自己的问号。恢复默认仍只改变草稿，核对后再保存。本次不改变 Agent/Bot 的新增入口。

## 配置行与上下文阅读

参数说明直接留在各字段旁，不再单独汇总成“使用指南”页面。配置行同时显示名称、输入值和说明；完整说明默认放在固定高度的单元格内，可直接滚动查看；“放大说明”展开该区域，“收回行高”恢复固定高度。窄屏时说明移动到名称和值的下方。

上下文默认按 JSON 层级展示；点击字段可单独折叠对象、数组或长文本。“展开一层”每次展开已显示的下一层，“收起内容”保留根节点。数组和对象每次增加 50 项，长文本在打开时才显示，避免一次生成过多页面元素。原文和下载仍保留。大快照会固定同一文件及版本分批读完，再解析；相同快照自动刷新时保留已展开的内容。

网页标签、侧栏、登录页与添加到主屏幕的应用图标统一使用蓝底「hi」。图标及 Web App manifest 定义在 `src/admin/icons.ts`，作为公开静态资源提供；管理接口仍需认证。

### 独立删除上下文快照

在“上下文”选择轮次和请求后，可用“删除这份快照”删除当前请求文件，或“清空本轮快照”删除该轮全部请求文件与初始编排快照。操作永久生效，不需要重启。运行中的轮次需结束后再删。删除不改聊天记录、压缩摘要、记忆和配置，也不改变第四层内存中已有的请求。删完请求后若还有初始编排快照，页面会显示它，可再单独删除。

### 手动向量化记忆

工作台“常用操作 → 立即向量化记忆”在后台补齐新增、修改或缺少向量的条目，可以继续聊天。下方显示已处理、已有向量、待处理和失败数量，每 2.5 秒更新；只有全部就绪才显示“向量化完成”。重复点击不会并行启动另一份任务，失败后再次点击会跳过已完成项。进度按记忆条数计算，不是预计剩余时间。
