# 2026-11-02：配置保存与运行链路审查

## 结论与范围

四层分工本身没有发现需要推翻的理由。当前问题集中在状态交接、配置生命周期和异常路径；功能存在不等于用户操作已经闭环验证。此前测试没有充分覆盖连续编辑、保存后再编辑、重启后继续使用，交付时把测试通过说成整体可用，结论过宽。

本轮检查了配置读取/继承/保存/重启、管理表单和文件接口、接入与附件、轮询与打断、历史及发送队列、上下文与记忆、Pi 与工具/MCP、调度脚本。自动测试覆盖具体可重复条件，不能证明所有平台、模型提供方及长时间运行组合均无问题。逐项帮助文本没有完成每个参数的真人体验验收。

## 配置保存到底怎么走

1. 页面修改进入一份浏览器配置草稿；个人值仍只写个人覆盖，缺省继续继承默认。
2. 保存时一并解析配置 JSON，提交草稿和读取时的文件版本。服务校验公共配置和每个 agent 的有效配置。
3. 服务串行检查版本、写文件、重新读取；页面再次读取核对结果。成功才清除草稿并重新生成表单，按钮旁持续显示结果。
4. 保存并重启继续重建组件，读取刚保存的文件。启动失败会明确显示旧配置仍在运行；新配置文件保留供修正。

已确认的原缺陷：保存后页面用服务器返回值替换配置对象，但旧 Agent 表单仍修改旧对象，所以后续输入可能没有进入下一次保存。配置 JSON 曾需要另点应用，否则普通保存忽略该编辑；保存通知又位于长页面顶部。版本号原来在重启后重置，旧页面还有覆盖新配置的风险。

**尚未确认：用户那次“几乎全部修改丢失”的完整触发路径。** 简单保存和重启在隔离复现中本来就可成功；不能把上面的已知缺陷当成那次故障的完整证据。实际浏览器里没有找到可恢复的暂存，也没有查到对应保存接口报错，不能承诺找回旧值。

## 本轮修复

| 问题 | 影响 | 处理与验证 |
| --- | --- | --- |
| 保存后旧控件仍引用旧配置 | 再次修改可能被漏存 | 成功保存后重建控件；测试并在浏览器重复保存 |
| JSON 未提交、提示不明显、无自动草稿 | 修改可能未进入保存，失败后难恢复 | 保存统一解析 JSON；操作栏显示状态；自动保留配置草稿 |

| 未知配置字段被静默去掉 | 看似保存，字段却消失 | 配置组严格校验并报错 |
| 记忆 JSON 暂时无效时清理旧索引 | 编辑错误可能让召回丢失 | 跳过此次同步，保留已有索引；重启后也验证 |
| 紧急压缩后仍保留超长原始消息 | 压缩无法解除超限 | 用摘要替代原消息，扣除 system/工具预算；真实执行器配本地模型模拟测试 |

## 暂不修改的审查发现

按用户要求，不把本轮扩展成零散功能修补。下面是尚未解决的具体边界，不代表已经验证无误。

- `src/admin/ui-client.ts` 的文件编辑器：保存请求尚未结束就切文件或继续输入，返回结果对编辑状态的处理还需要单独验证和收紧。配置表单已处理；文件编辑器不能据此算已修。
- `src/admin/control.ts` 的凭据写入：两个页面同时写同一份 .env 的不同变量，读改写存在互相覆盖的窗口。普通串行保存不触发这个条件。
- `src/layer4/pi.ts`：关闭工具总开关仍可能初始化 MCP 连接；实际工具未注册，但关闭开关应否连带停止连接需要修正。
- `src/layer3/memory.ts`：关闭短期激活后，已有激活分数仍参与部分计算，开关语义不完整。
- 开发模式 TSX 下，浏览器提示词预览函数的序列化存在辅助符号依赖；正式编译产物未遇到该问题。
- 多个配置文件分别原子写入，普通异常可回滚；突然断电或强杀中途不具备完整跨文件事务。
- Token 预算是估计值；图片实际占用、提供方协议差异、超长历史的性能和长时间真实渠道运行仍需要专项验证。
