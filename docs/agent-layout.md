# 每个 Agent 的配置与定时任务

主目录放公共设施和公共默认值；`agents/<id>/` 放这个 agent 自己的设置、凭据、脚本和经历。`workspace/` 只是它放工作产物的子目录，不是所有个人文件的根目录。

```text
hineni-agent/
├── config.yaml              公共连接、端口、目录；可继承的默认设置；agent ID 清单
├── .env                     HINENI_TOKEN、Bot Token、Webhook 连接密钥、Telegram 代理
├── data/                    共用数据库，按 agent_id 区分经历索引、队列和运行记录
├── prompts/system.md        新建 agent 的基础提示词模板
├── scripts/schedule.ts      新建 agent 的调度脚本模板，日常运行个人目录的脚本
└── agents/<id>/
    ├── config.yaml          自己的模型、记忆、情绪、工具、发送、调度和聊天绑定
    ├── .env                 自己的模型 Key、MCP 请求头等凭据
    ├── schedule.ts          自己的定时脚本（可在自己的配置里更换相对路径）
    ├── prompts/system.md    自己的基础提示词
    ├── SYSTEM.md            自身环境说明，供模型按需阅读
    ├── persona.md / memory.json / state.json
    ├── history/ / attachments/ / skills/ / .runtime/
    └── workspace/           工作文件和生成产物
```

## 配置怎样继承

逐字段读取：自己的 config.yaml 明确写了就用自己的；没写就用根配置默认值。普通保存保持缺省项，不把实际生效值自动抄回个人文件。false、0 和空数组都是明确配置；数组整体替换，不逐项合并。

网页会显示“自己设置”或“继承默认”。“恢复继承”删除自己的字段；“复制当前默认值”明确把默认值写进个人草稿，保存后不再跟随该字段的默认值变化。高级 JSON 显示个人覆盖项，删除字段表示继承，整组 null 表示恢复整组继承。

新 agent 的个性参数默认留空、继承公共配置；提示词和调度脚本仍复制一份独立文件。现有 main 在上次迁移时保存的完整个人值继续保留，不擅自删除；需要跟随默认时，使用恢复继承。

根目录 `config.yaml` 的 `agents` 只保留 ID 清单，例如 `[{id: main}, {id: another}]`。每个子目录的 `config.yaml` 用顶层 `models`、`memory`、`scheduler` 等字段，不必手写 `overrides`。管理 API 为兼容原表单仍返回合并视图，其中 `agents[].overrides` 对应子目录的设置；保存时 ConfigStore 拆回各文件。

新增 agent 默认停用。保存后会创建独立配置、空的模型凭据文件、提示词和脚本；重启时补齐人格、记忆、Skills 等文件。先填写它自己的 Key 和消息绑定，再启用。不会复制另一个 agent 的 Key、记忆或当前情绪。

## main 的定时任务改哪里

随机摸鱼/纯聊的间隔、时段、开关、每日机会数和三项权重写在 `agents/main/config.yaml` 的 `scheduler`；等待、时段判断和提醒文字写在 `agents/main/schedule.ts`（`randomGreeting`）。改数字只改 config，改文字或新增任务改脚本。自定义任务可以直接在脚本里写时间和逻辑，不强制增加配置项；新参数只有被代码读取才会生效。

保存后重启 main 的定时脚本，宿主会重新读取并校验磁盘配置，再启动个人脚本。主程序自动保持脚本运行。脚本到点向统一 `/v1/events` 提交带 main ID 的内部事件，由第二层记录并轮询接手，再经过第三、第四层；回复走 main 的默认渠道。

## 触发点放哪里

- Bot 账号、连接方式、渠道允许列表、HTTP 监听端口：主目录配置和 `.env`。
- 哪些聊天交给自己：自己的 `defaultTarget` / `routes`；主动消息默认位置和目标别名也放自己的配置。
- 什么时间、因为什么主动触发：自己的 `scheduler` 参数和 `schedule.ts`。
- `/v1/events` 仍是同一个公共入口，事件必须有 `agent_id`。普通消息、脚本、手动触发都走原协议，不增加另一套推理入口。

## 凭据怎样读取

模型页保存 Key 到当前 agent 的 `.env`；Telegram 页保存 Bot Token 到主目录 `.env`。两个 agent 可以都使用变量名 `OPENAI_API_KEY`，值不同，互不覆盖。缺少自己的 Key 会报缺失，不借用其他 agent 的 Key。

程序把自己的环境单独传给该 agent 的主模型、辅助模型、网页搜索、Bash 和 MCP；不会把各 agent 的 `.env` 合并进公共 `process.env`。MCP 子进程还可用自己的配置 `mcp[].env` 明确覆盖。管理连接令牌只为调度进程额外注入，以便向公共接口提交事件。

这是配置与运行上下文隔离，不是操作系统权限隔离。文件工具仍有当前账户的读写权限；明确读取另一个目录或主动修改共享配置仍然可能。

## 保存、重启和直接编辑

| 修改                                          | 生效方式                                                         |
| --------------------------------------------- | ---------------------------------------------------------------- |
| 模型、记忆、情绪、工具、聊天绑定或 `.env`     | 保存并重启主程序；会停止所有正在进行的推理，但保留记录和发送队列 |
| 自己的 `schedule.ts`，或只改 `scheduler` 参数 | 保存后重启当前 agent 的定时脚本；其他 agent 不受影响             |
| 自己的人格、基础提示词、Skills                | 保存后下一轮读取                                                 |
| 主目录默认配置                                | 重启后影响所有仍继承相应字段的 agent；个人明确值不变             |
| 主目录提示词/脚本模板                         | 以后新建时复制，已有个人文件不跟随                               |

AI 可以编辑自己的脚本，调用 `restart_scheduler`；这个工具绑定当前 agent，不能用参数重启别人。网页文件编辑器的“重启定时脚本”同样针对当前 agent。管理 API `POST /v1/scheduler/restart` 接受 `{agent_id:"main"}`；省略 ID 是管理员重启所有脚本的兼容用法。

每个 agent 有一个独立子进程。脚本退出后约 5 秒重启自己的进程；重启从头计时，不保存下次触发点，不补跑离线任务。一个脚本语法错误不会停止其他 agent 的脚本。任意自定义任务列表/逐任务暂停仍由各自脚本实现，程序不会自动识别脚本里的任意任务。

手动触发一次招呼：在项目根目录执行 `node --env-file=.env --import tsx agents/main/schedule.ts --once random_chat --agent main`。直接执行 main 自己的脚本并读取其配置，走同一个 `/v1/events`，不启动常驻计时，也不重置其他进程；绕过随机聊天开关和活跃时段。

外部直接修改配置后，网页“重新读取”会读取磁盘；未重新读取时保存会报版本冲突。模型密钥不出现在配置 API 或普通文件编辑器里。配置校验通过后逐文件原子替换，普通写入失败会回滚；跨文件保存不具备断电事务保证，备份须包含根配置、所有 agent 目录和 data。

## 旧版本迁移

首次加载旧布局时，把每个 agent 原有的有效配置展开到自己的文件以保留行为（已迁移的个人值保留；普通保存不再补齐缺省字段）；把模型凭据复制到对应 agent 的 `.env`，从根 `.env` 移除非连接用途的模型变量。Bot Token、管理口令与代理保留。已有私人文件不覆盖，聊天和数据库不搬动。运行本次迁移前已另行备份旧配置与程序；源代码入口为 `src/config/store.ts`。

## 一次性提醒与可编辑的小模型规则

见 [一次性任务与小模型行为](configuration-guide.md#给自己设置一次提醒)：个人 schedule.once.json 的生命周期、UI 保存与重启、auxiliary.yaml 的读取优先级，以及情绪评分和表达映射。现有定时脚本、原始经历和模型协议保持不变。

状态分档与时间提示也可单独配置：个人 `prompts/prompt-mapping.yaml`，在配置页点“编辑状态与时间映射”，保存后下一轮读取。详见 [映射文件说明](configuration-guide.md#状态与时间映射)。评分配置与辅助模型提示词保持原文件分工。
