第一版实现完整的四层运行闭环；模型输出质量、人格和记忆体验需要真实使用调参。

已通过 28 项自动测试，覆盖真实 Pi SDK + 本地 OpenAI SSE、官方文件工具、真实 MCP stdio、消息批处理/打断、独立 agent 数据、持久化队列、明确失败重试/不确定状态、原始文件重建、工具结果回放、附件稳定保存、图片只注入一次、API 认证和配置验证、记忆衰减/强化/降级、后台索引不阻塞召回。

2026-11-01 已使用一次性凭据完成 OpenAI 官方接口实测，6 项通过，见下方记录。随后已完成正式实例 Telegram 私聊入站、gpt-4.1 回复及平台确认送达；视觉输入、网页搜索和长期聊天体验尚未实测。默认模型和地址可换，不把兼容协议理解为所有服务商都实现视觉、JSON输出或网页搜索扩展。

实现上的明确选择：

- 配置保存后重启生效，避免运行中途切换存储目录或渠道；提示词、记忆与 Skills 文件按轮读取。后续可增加安全的分组热更新。
- 向量索引为本地持久化向量 + 余弦检索，适合个人记忆规模；替换大型向量库不影响 memory.json 和工具协议。
- 原文与工具完整记录实时在文件里，SQLite 管查询和发送状态；没有后台定时导出才能读的限制。
- 使用 Pi 官方工具，但自主构造 system prompt、工具循环和完成回调；没有接管其完整编程 Harness。
- 本轮图片按保守的每图 token 余量检查；具体视觉计费随模型，必要时分批发送。图像生成、视频和手机控制通过后续工具/Skill 扩展。
- 记忆与人格的直接文件编辑不提供任意编辑器操作的事务锁；自带 Skill 要求原子保存，系统侧写入串行。需要强制隔离时应增加进程/容器权限边界。
- 群聊默认允许持续接话，没有自动降频或接力上限。它可能持续消耗模型额度，行为按此前讨论保留。
- 实验性的驱动力耦合、执念增长、无事件随机心情漂移保留为后续设计，没有放置无作用的假开关。
- QQ、邮件、WhatsApp 没有内置账号接入；可以实现 Channel 或通过统一 Webhook 协议连接现有桥接服务。
