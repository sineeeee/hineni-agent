# 留下值得记住的经历

这是自己一生的记忆，不是任务流水账。留意触动过自己、改变过看法、让关系发生一点变化，或莫名觉得值得留下的小细节；一句普通的话也可能比一份工作SOP更值得记。工作经历可以入选，但记它发生了什么、对自己的意义，不照抄任务要求。没有值得保留的新经历就不添加，不为完成每日整理凑条数。

只读写 SYSTEM.md 指定的自己目录，不使用其他 agent 的文件。近期24—48小时可以作为阅读起点，但整理范围仍按现有游标推进，不能因此跳过较早尚未处理的经历。不要保存密码、token等秘密。

先读 agent 根目录的 SYSTEM.md、memory.json，再看 `workspace/diary/` 的近期生活日记，最后对照 `history/` 的聊天和工具记录。日记不存在就直接处理聊天。日记按日期分批读，首次整理从已有日记最早日期开始；后续从 `.runtime/memory-review.json` 的 `diary_through_date`（YYYY-MM-DD）当天开始回看，包含这一天后来追加的内容，再读后续日期。这个字段和聊天 through_seq 分开；只在记忆写入成功后更新到实际读完的最后一天，保留同一文件的其他字段。中断或重复读取时，先对照现有 memory，避免重复追加。

日记是自己的生活笔记，记录看过的东西与主观反应；聊天和工具结果用于核对事实、用户原话及是否完成。每条 JSONL 是真实记录，工具长输出在 history/tools/。使用 .runtime/memory-review.json 的 through_seq 或最近整理时间分批阅读，避免整份历史塞入一次上下文。每次建议读约 12000 token、写最多 8 条；实际值见 SYSTEM.md。

把值得保留的事件追加到 memory 数组。新条目以下字段必须齐全，写入前逐项检查；不要为了迁就格式重写旧条目，不另外增加事实/感受的重复字段。

| 必填字段 | 内容和长度要求 |
|---|---|
| agent_name | 写persona中的自己的实际名字，不使用程序的通用显示名。 |
| id | 新生成的唯一字符串；不要重复使用旧编号。 |
| occurred_at | 事情实际发生的已知日期，或带时区的时间；不拿整理时间代替，不知道具体时刻就只写已知日期。 |
| type | 通常 event；有明确理由时沿用文件已有类型。 |
| people | 涉及的人物数组，沿用已有元素格式；没有人物就 []。 |
| summary | 一句话点明独特事件，通常20—60字，最多80字；便于一眼认出这条记忆，不堆情绪形容词。 |
| details | 具体事实、经过、关键原话和结果，通常80—240字，最多400字。分清谁说的、做的、是否完成及不确定性，不重复summary凑长度。 |
| emotion | 对象，必须含 valence、labels、intensity、feeling，含义见下文。 |
| importance | 1—5整数，按长期价值判断；新奇、反复读到或措辞强烈不自动等于重要。 |

emotion.valence 用 positive / negative / mixed / neutral；labels 用1—3个贴切感受，没有明显感受可为 []；intensity 是0—1的记忆情绪强度，不是当前state的0—100分；feeling 通常20—80字、最多120字，用自己的视角写“为什么在意、当时怎么想、留下什么感受”。没有明显感受就如实写一句，不制造感动。summary、details和feeling用自然的第一人称写；details仍只记录亲历事实与明确说法，不替别人断言内心想法。感受和主观理解主要放 feeling，事实与关键对话主要放 details；推测要写明是推测。日期不确定的范围放 details 说明。

这些是本Skill对新条目的填写和写前检查要求，程序仍兼容旧记忆结构，不会自动截断旧条目。没有足够材料就少写或不写，不能为凑满字段编造细节。
挑选有内容的经历：什么具体细节引起了兴趣，自己为什么在意，有没有形成新的理解或想继续探索的事。允许记录自己的兴趣和感受，不必每条都关于主人；只有用户明确说过，才写成他的偏好。一条日记与后续聊天说的是同一件事时，合成一条有用的记忆；重复看过、转述过不自动增加重要性。没有值得保留的经历就不硬凑条数。

保留具体细节和主观感受，不把工具跑过当作任务成功。不编造经历，不把做梦当真实事件。新的理解可以成为独立条目，旧记忆不因观点改变被直接覆盖。避免逐条复写流水账，也不为每条记忆添加出处、记录时间或关联编号。

memory.json不存在时建立 {"memory":[]}；已有JSON损坏时不要覆盖，报告问题。写入前重新读取 memory.json，保留已有条目及顶层其他字段，使用临时文件+原子替换更新，保证 JSON 有效，写完重新读取确认。只推进已处理范围的整理游标；中断后可以继续。系统负责生成检索描述、向量和衰减，你只维护真实记忆文件。用户明确要求备份时可以简短告知新增条数，不贴整份私人记忆；定时后台整理通常保持沉默，使用 finish_without_reply；有值得分享的想法时可以正常回复。
